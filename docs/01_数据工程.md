# 数据工程：维护者准备、学生划分与可选合成

对应 [00 Baseline Diagnosis](../00_Baseline_Diagnosis.ipynb) 和可选 [01 Synthetic Data Engineering](../01_Synthetic_Data_Engineering.ipynb)。正式任务为 Numeral System、Gravity、Equation Numeric；Bit 保留在历史实验及高级扩展中。

## 职责边界

| 执行者 / 文件 | 工作 |
|---|---|
| 维护者：[prepare_official_dataset.py](../utils/prepare_official_dataset.py) | 读取官方 CSV；核验字段和重复；分类、筛选；逐条核验 Numeral 映射；分发已清洗数据及来源 Manifest |
| 学生：00 | 读取已清洗数据并核验契约；80/10/10 划分；跨集合泄漏审计；保存划分、Manifest、审计报告；Validation Baseline |
| 学生：01（可选） | 根据 Train 先验合成候选；独立验证与三集合泄漏审计；保留 Candidates / Accepted / Rejected |

维护者运行 `python utils/prepare_official_dataset.py`。默认输出目录为 `data/processed/tasksets/roman_gravity_equation_v1/`。
工具不修改原始 CSV，不生成划分，不加载模型。同版本文件内容不同会报错，避免覆盖已有实验资产。

## 00 的输入与输出

输入为 `real_cleaned.csv` 和 `official_preparation_manifest.json`，包含原 ID、原始 Prompt/Answer、题型、来源行号、来源数据集及 SHA256。
分类审计与映射审计作为维护者证据一并分发；Notebook 不重新分类、过滤或写回清洗文件。

00 按题型、种子 42 分配 Train 80%、Validation 10%、Holdout Test 10%。Validation / Holdout 各四舍五入到最近整数，其余归 Train。输出三个 CSV、`dataset_manifest.json`、`dataset_statistics.json` 和 `leakage_audit_report.json`。

审计区分以下情况：

- ID、精确 Prompt、规范化 Prompt 的真实跨集合重复。
- 掩去字面量后的结构相似；不直接认定同源，也不宣称 Structural OOD。
- Numeral Query 映射在其他集合示例或目标答案中的直接暴露；单独列出，不能与完整样本重复混为一谈。

规范化统一 NFKC、空白和大小写，保留具体数值与运算符。当前 IID Numeral 的有限映射存在答案暴露，因此不能将较高准确率解释为未见映射泛化。

Baseline 的预算校准与正式评测均使用 Validation，两批样本 ID 不相交。Holdout 只用于固定审计及未来最终评估，不参与预算选择、Prompt 调整或合成生成。

## 01 的可选增强

生成分布仅来自 Train。候选必须先由独立 Verifier 检查答案、轨迹和 Identifiability，再与 Train / Validation / Holdout 的精确 Prompt、规范化 Prompt、来源 ID/行号及结构指纹交叉审计。
真实重复和来源命中会拒绝；结构相似单独报告。所有拒绝原因保留，未经独立验证和 Leakage Audit 的样本不得进入 Accepted。NeMo Preview 继续单独保存，不直接作为 Ground Truth。

01 不阻塞后续 SFT：现有 03 默认读取维护者分发的非合成真实 Train 轨迹，显式设置 `USE_SYNTHETIC_DATA=1` 才读取配置路径中的已审核 Accepted。02–06 本轮仍保留历史数据接口，尚未自动接入新版三任务；其训练算法与模型路线不变。
