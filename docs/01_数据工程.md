# 数据工程指导：Real Dataset、Synthetic Data 与质量筛查

版本：v0.1 \| 对应 Notebook：`01_Baseline_Evaluation` 的数据准备部分

## 1. 目标与边界

真实数据清洗为必做；合成数据生成与筛查为选做。课程统一提供三类任务的人类先验：

-   Gravity：物理公式、参数定义和数值约束。
-   Equation Numeric：候选运算规则及全局约束。
-   Bit Manipulation：基础位操作定义和表达式语法。

学生不需要重新发现隐藏规则。数据工程要完成官方数据清洗、分区、可选合成、独立验证和数据质量分析。所有代码写在
Notebook 中，不创建 `.py` 文件。

## 2. 先处理官方真实数据

### 2.1 清洗顺序

1.  读取官方 `train.csv`。
2.  检查字段、类型、缺失值和重复 ID。
3.  统计原始题型分布。
4.  抽样检查各题型 Prompt。
5.  实现题型分类器。
6.  只保留 Gravity、Equation Numeric、Bit Manipulation。
7.  将 Equation Numeric 与 Equation Symbolic 分开。
8.  将无法确定类别的样本单独保存审计。
9.  输出清洗前后统计报告。

不能把所有包含 `Equation` 的样本都保留。分类逻辑必须经过实际 Prompt
抽查。样本数量以当前 `train.csv`
的程序化统计为准，不硬编码此前讨论中的数字。

### 2.2 清洗输出字段

至少保留
`id`、`prompt`、`answer`、`task_type`、`source`、`raw_task_label`。不得覆盖或修改原始
`train.csv`。无法分类的样本不能静默丢弃。

## 3. 数据划分与泄漏控制

### 3.1 先划分，再生成

真实数据必须先划分，再生成合成数据。初始比例可考虑 Train 80%、Validation
10%、Holdout Test 10%，但应根据清洗后的类别数量和分组结构调整。

### 3.2 分组规则

优先使用原始样本 ID、规范化
Prompt、规则配置、表达式结构、模板来源和数据增强来源 ID
识别同源样本。同一原始题目产生的增强样本必须进入同一分区。如果无法可靠识别分组变量，应明确记录限制，不能宣称已经彻底消除泄漏。

### 3.3 两类评测

-   **IID Holdout**：测量与训练分布相近的泛化能力。
-   **Structural
    OOD**：测量未见规则组合或表达式结构的泛化能力。该项为选做。

Validation / Holdout Test
不得参与合成训练数据生成、筛查阈值选择或规则生成器调参。

## 4. 选手报告中的数据工程经验

### 第一名：先统计先验，再生成问题和 Solver Trace

第一名复现仓库的流程包括：从 `train.csv`
建立数据划分、统计规则和分布、构建合成先验、生成问题、生成教师轨迹、筛查并聚合训练集，最后进行两阶段
SFT。其数据量和 GPU 时长远超本教程预算。

**迁移：** 学习 Prior → Generator → Solver → Trace → Screening
流程，不复制数据规模。

### 第二名：快速迭代合成 Prompt 与 CoT

第二名使用代码生成合成 Prompt 和 CoT，重点覆盖 Bit
Manipulation，并强调轨迹检查。作者尝试 Focal Loss、Token Reweighting
和多阶段训练，但未发现它们稳定优于标准交叉熵。

**迁移：** Generator 与 Trace Builder
分离；合成数据必须可验证；先建立标准 CE 基线。

### 第三名：选择性增强

第三名对部分任务增强数据，并将 Memorization 与 Execution
分成两个阶段。Gravity、Unit Conversion 和 Numeral 没有额外增强。

**迁移：** 不对所有任务平均扩充，优先定位需要增强的任务和能力。

### 第九名：不增加合成问题，也能改善结果

第九名没有进行额外 Synthetic Problem Expansion，而是修订
CoT，使其更一致、更容易人工审计。

**迁移：** 合成数据不是必需条件；先检查轨迹质量，再决定是否增加数据。

### 第十五名：Targeted Drill

第十五名将容易失败的局部操作拆成 Drill，再混入完整任务训练。

**迁移：** Drill 应由错误分析驱动，不应无差别重复所有基础规则。

### 第八十名：Failure-driven Synthetic Data

第八十名研究失败样本的结构分布，并提出针对稀有 CHOICE / MAJ
等规则构造定向合成数据。

**迁移：** 合成数据应由真实错误分析驱动，而不是只为扩大数据集。

### 第十名：Solver 不得读取标准答案

第十名强调教师 Solver 必须从 Prompt 自身推导答案，不能读取 Ground Truth
后再反向构造推理过程。

**迁移：** Teacher Trace 必须
Prompt-derivable。不能将只有看过标准答案才能得出的信息写进推理过程。

## 5. 三类合成数据生成器

先做 Pilot，每类约 100 条用于检查生成器和 Verifier。100
条只是调试规模，不是最终训练规模。

### 5.1 Gravity Generator

输入先验：物理公式、参数定义、单位和精度规则。生成流程：采样参数、生成示例、生成
Query、计算答案、检查数值范围和格式，再用独立逻辑验证。Gravity
主要用于基础能力覆盖，不应过度生成。

### 5.2 Equation Numeric Generator

输入先验：候选运算规则、数字反转规则、正负号格式规则、同题全局约束、Deduce
/ Guess 定义。

生成流程：采样规则、采样操作数、生成示例和
Query、计算答案、检查示例是否足以约束规则、检查不同候选规则是否对 Query
给出不同答案。Deduce 与 Guess 必须分开标记。不能将规则未出现的 Guess
题误标为唯一可解的 Deduce 题。

### 5.3 Bit Manipulation Generator

输入先验：8-bit 位操作、Shift / Rotate 参数范围、AND / OR / XOR / NOT
和允许的表达式语法。

生成流程：采样表达式、采样参数、采样输入字节、计算示例输出、生成
Query、检查表达式是否合法、检查候选表达式是否在 Query
上产生不同答案。只保留可识别样本。

表达式深度可以用于分层，但不能直接把表达式更长等同于更难。最终难度需要结合模型实测准确率。

## 6. 独立质量筛查

Generator、Solver 和 Verifier
尽量独立实现。不能使用同一个函数生成答案，再用同一个函数证明答案正确。

  检查                  目标
  --------------------- -------------------------------------
  Schema Validation     字段和类型正确
  Answer Verification   最终答案正确
  Trace Verification    每个中间步骤可复算
  Identifiability       示例能够确定 Query 的唯一答案
  Deduplication         精确重复和近重复
  Difficulty Audit      难度区间符合预期
  Distribution Audit    规则、参数和结构分布可控
  Leakage Audit         与 Validation / Holdout Test 无交叉

被拒绝的样本必须保留拒绝原因。输出生成数量、通过数量、拒绝数量、拒绝原因、接受率、规则覆盖率、难度分布和
Token 数量分布。

## 7. 数据实验

  实验   训练数据                    目标
  ------ --------------------------- ----------------------------
  D0     Real Only                   建立真实数据基线
  D1     Real + Raw Synthetic        测量未经筛查合成数据的影响
  D2     Real + Screened Synthetic   测量质量筛查的影响

控制相同模型、SFT 目标、训练 Token Budget、训练步数和评测集。分别报告
IID 与 Structural OOD。

## 8. 交付物

-   清洗后的三类真实数据；
-   Train / Validation / Holdout Test 划分；
-   题型分类审计表；
-   可选的三类合成数据；
-   合成数据筛查报告；
-   数据来源和生成配置元数据；
-   Real-only 与 Real + Synthetic 对照结果。
