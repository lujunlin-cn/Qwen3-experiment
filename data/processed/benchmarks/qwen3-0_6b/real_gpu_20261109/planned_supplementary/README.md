# 可选补充实验预登记：当前仅 CPU 准备

两个方案均在原始完整实验首次使用最终面板之前准备，尚未请求 GPU，不是已取得
的效果。只在原始四方法实验结束、质量目标仍未满足且原有 GPU 时间足够时选择
执行；不自动延长预算，也不改变正在运行的源码或原始结果。

- `precision_replay/`：从同一个 NF4 SFT 第 1 轮权重和 Adam 状态出发，以相同
  数据、顺序、Seed 和更新数进行两轮 BF16 续训，再与原 NF4 第 3 轮对照。
  用于检查训练精度与 BF16 部署精度的影响，不预先断言它就是质量下降的原因。
- `quality_followup/`：最多一小时的 SFT/DPO 定点补充。使用 BF16 SFT、较高
  学习率，以及更多 DPO 微批更新和 16384 候选上限。损失函数、奖励、独立
  Solver/Verifier、数据拆分和最终评测口径不变。DPO 只有在预先指定的 SFT
  调参质量及长度门槛满足时运行，避免继续花时间生成无效偏好。

这些是原服务器上的定点重现脚本，必须在仓库根目录执行，要求完整的原始
`course8h_20261109_r2_cuda_graph` 运行目录、模型及三套环境。其冻结源码版本为
`98787e2`，与本地后续 NeMo Trace 加固版本不同；源码哈希不符会拒绝运行。
脚本已完成真实 CPU prepare，配置、面板和初始权重哈希已注册，GPU 状态仍待验证。
修改脚本或参数必须使用新 Run ID，不能覆盖已经登记的方案。

最终面板不用于选择 checkpoint；质量补充与原始完整实验分开报告。共享基线对照
只在问题 ID、提示词版本、Seed 和输出上限一致时比较。不能把补充 SFT/DPO
与原实验 PPO/GRPO 混写成同一个 SFT 起点的完整四方法对照。
